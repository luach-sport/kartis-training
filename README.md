# כרטיס (אימון) 🎟️

אפליקציית אימון לרכישת כרטיסים להופעות — **הכול מדומה**: ההופעות דמיוניות ואין תשלום אמיתי.
המטרה: להתאמן על בנייה של אפליקציה "רצינית" עם חשבונות בענן.

**הורדה:** [kartis.apk — הגרסה האחרונה](../../releases/latest/download/kartis.apk)

## מה יש באפליקציה

| יכולת | איך זה עובד |
|---|---|
| התחברות עם Google | חלון בחירת החשבון של אנדרואיד (Credential Manager) → אסימון זהות → Firebase Auth |
| הרשמה עם מייל וסיסמה | Firebase Auth. הסיסמה לא עוברת דרכנו ונשמרת מוצפנת אצל גוגל |
| אימות מייל | מייל עם קישור. בלי אימות — השרת מסרב לרכישה |
| איפוס סיסמה | "שכחתי סיסמה" שולח קישור למייל (בעברית) |
| נתונים בענן לכל משתמש | Cloud Firestore: `users/{uid}` ומתחתיו הזמנות ומכשירים |
| כמה מכשירים לאותו חשבון | כל מכשיר רושם את עצמו; הכרטיסים מתעדכנים חי בכולם |
| ניתוק מכשיר מרחוק | מוחקים את המכשיר מהרשימה → הוא מתנתק לבד |
| עבודה בלי אינטרנט | עותק מקומי של הנתונים; שינויים נשלחים כשהחיבור חוזר |
| אבטחת מידע | `firestore.rules` — כללים שרצים בשרת ובודקים כל קריאה וכתיבה |
| מלאי משותף | רכישה = טרנזקציה: הזמנה + עדכון מלאי יחד; אי אפשר למכור יותר ממה שיש |
| מחיקת חשבון | אישור זהות מחדש → מחיקת כל הנתונים והחשבון (דרישה של גוגל פליי) |
| מנהל | מי שרשום ב-`admins/{uid}` טוען הופעות ופותח/סוגר מכירה |

## מבנה הקוד — הרבה קבצים קטנים, כל אחד עם תפקיד אחד

```
src/
  main.js               נקודת הכניסה
  config/               הגדרות: פרטי Firebase, מגבלות
  firebase/             אתחול: app, auth (התחברות), db (מסד נתונים)
  services/             כל הדיבור עם הענן — מסכים לא מדברים עם Firebase ישירות
    auth-service.js       הרשמה, כניסה, איפוס, אימות, יציאה
    google-signin.js      Google בטלפון / בדפדפן
    profile-service.js    פרופיל
    devices-service.js    המכשירים של החשבון
    shows-service.js      הופעות
    orders-service.js     רכישה וביטול (טרנזקציות)
    admin-service.js      כלי מנהל
    account-service.js    מחיקת חשבון
  core/                 עזרים בלי ענן: ניתוב, מצב, ולידציה, פורמט, מלאי, שגיאות
  app/                  חיבור הכול: מסלולים, מסגרת, סשן
  ui/components/        רכיבים: כרטיס הופעה, כרטיס, שדה, כפתור Google...
  ui/screens/           מסך בכל קובץ: auth / shows / checkout / tickets / account / admin
  styles/               עיצוב, קובץ לכל חלק
firestore.rules         כללי האבטחה
tests/
  unit/                 בדיקות של הלוגיקה
  rules/                בדיקות כללי האבטחה (כולל ניסיונות "פריצה")
  integration/          זרימה מלאה של הקוד האמיתי מול אמולטור
  mock-services/        ענן מדומה, לניסוי המסכים בדפדפן
```

## הרצה מקומית

```bash
npm install
npm run dev:mock     # כל המסכים בדפדפן, בלי Firebase (ענן מדומה)
npm test             # בדיקות לוגיקה
npm run test:rules   # בדיקות אבטחה + זרימה מלאה (צריך Java 21)
```

## בנייה

כל push ל-`main` מריץ ב-GitHub Actions: בדיקות → בניית האתר → פרויקט אנדרואיד (Capacitor) → APK חתום → Release.

> ⚠️ **מפתח החתימה** (`signing/training.jks`) והסיסמה שלו גלויים בכוונה — זו אפליקציית אימון.
> באפליקציה אמיתית שומרים את הסיסמה ב-GitHub Secrets ואת המפתח במקום בטוח.

הגדרת Firebase צעד אחר צעד: [docs/firebase-setup.md](docs/firebase-setup.md)
